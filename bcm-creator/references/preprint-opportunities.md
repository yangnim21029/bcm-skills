# Find research that could improve a mapped task

Use arXiv to investigate methods, tools, datasets or research directions worth reading and potentially testing within the unit's capabilities. Investment means committing staff time, development effort or resources to that work. A paper is a lead, not evidence that the organization should fund it.

## Establish the search scope

Reuse the capability map, confirmed objective, institutional boundaries and known gaps. State whose work each direction concerns and what would improve. Keep inferred needs conditional. Include credible alternatives and existing institutional work; a convenient paper must not select the unit's priority. A proposed extension beyond the map needs an explicit rationale and separate label.

For a full investment brief, make a bounded search after the initial capability analysis. For an explicitly requested paper list, reuse that analysis without rebuilding the map. Prose-only revisions reuse collected evidence. Use available academic-research-suite workflows for targeted discovery and verification; a targeted search does not imply a systematic review.

## Search and retain the record

Translate each work problem into task terms and technical synonyms. Search promising approaches and evidence against them, including simpler baselines, failure cases and different populations. Follow references or code links where they could change a decision. Expand searches to resolve a material gap rather than accumulating supportive papers.

Record each exact query, service, date, fields/categories, time range, sorting, page/record limits and records retrieved. Distinguish reported hit totals from fetched records and papers actually examined. Deduplicate versions by arXiv ID while retaining version dates and discovery queries. Keep every retrieved paper, including unsuitable and unread items, with its disposition. Disclose truncated searches and inaccessible papers; do not imply exhaustive coverage.

## Verify the research

Retrieve the original arXiv record and the cited version. Verify title, authors, dates and working links; identify preprint status and verify any claimed publication separately. Read methods, results, tables and limitations before recommending a trial. Use liteparse when available for PDF extraction. State whether only metadata, the abstract, selected sections or the full paper were read.

Check task, population, comparison, metric and denominator. Before claiming a detail is unreported, search the full text and check the relevant section. Distinguish benchmark improvement from the unit's work outcome. Verify claimed code, data, access and licenses separately. A repository link alone does not establish usable code or permission. Prefer retrievable primary evidence; neither an arXiv posting nor a venue's reputation substitutes for examining the study. Do not invent a DOI, result, deployment or return on investment.

## Explain the possible use

For each promising paper, explain the work situation, material supplied, what the proposed tool would show, what the person would do next, and which existing step might improve. Use the paper's actual method and the unit's scope. Describe the original process as unknown when it has not been observed. Explain the connection to the proposed benefit; a technical feature alone is insufficient.

State what resources would be needed, what evidence transfers poorly, a simpler comparison and a small next check that could reject the idea. Keep reading priority, suitability for a trial and funding approval separate. Apply the complete-explanation review to inclusion reasons and exclusions as well as recommendations.

## Deliver a readable comparison

Use a plain HTML table for this paper inventory, an exception to the default against tables in narrative briefs. Include all retrieved unique papers. Suggested columns: paper/version and link; capability and proposed use; research evidence and read depth; missing conditions; disposition with reason. Use complete explanations in cells. Mark papers as worth reading, conditional, background, unsuitable for this task or not assessed; explain each judgment without invented scores.

Place exact queries, scope and coverage counts beside the table. Reconcile retrieved, duplicate, assessed, unsuitable and unread counts. Use compact citations with original passage routes. Keep raw retrieval and detailed evaluation records internally; deliver no additional Markdown or JSON downloads unless requested. Deliver research-opportunities.html automatically for every full brief, sharing navigation with the other three pages; a paper-list request can deliver it alone. Keep the page static and directly readable, without filters, dialogs or concealed results.
