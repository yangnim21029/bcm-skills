# 分輪問答：先確認決策與可用資料

新的公司分析或投資評估，先進行這段問答，再展開外部搜尋。問答的目的，是讓使用者補充分析範圍、真正要做的決策，以及哪些資料能直接供本次分析使用。使用者可以回答一部分、提供文件位置、表示尚未決定，或明確略過。

先沿用本次對話、使用者指定文件及既有分析紀錄中的答案。只問仍缺少、會影響判斷的部分；單純改寫文風、翻譯或重新排版時，沿用原範圍，不重新啟動問答。從 `bcm-creator` 接續到 `ai-opportunity-radar` 時，共用同一份問答紀錄。

同時分析多家公司時，共通目的、期間與資料偏好先問一次；各公司的業務範圍、可用資料和未明條件分別記錄，再針對差異追問。

## 互動方式

一次提出一至三個簡短問題，收到回答後才決定下一輪。使用可用的互動問答工具；若工具不支援，就以短訊息提問。不要一次貼出完整問卷，也不要要求使用者先填滿七個分析面向。

選項要包含清楚的「這題先略過」或「略過後續問答，先用現有資料分析」。可讓使用者自由回答，勿把建議選項當作已選答案。文字問答工具可收文件路徑、連結或簡述；不要在只支援文字的工具內要求上傳檔案。使用者表示有資料可提供時，先問資料種類與可用位置，再讀取實際內容。

提出尚待回答的問題後，先整理已取得的資料或處理其他獨立工作。不要把沉默、逾時或預選選項記成同意、答案或略過。使用者在任務中已明確要求「直接使用公開資料、不要提問」時，視為已選擇略過，繼續分析。

## 第一輪：確認範圍與決策

公司名稱可能指向多個法人或品牌時，先確認使用者指的是哪一家。關係企業、合作夥伴及不同地區是否納入，依使用者的決策需要確認，勿因搜尋結果相鄰就合併範圍。

先辨認使用者尚未交代的部分，再從下列問題挑選：

- 「這次要看哪個範圍？可以涵蓋整家公司，也可以指定事業、產品、地區、客戶或合作關係；有哪些部分要排除？」可用選項：整家公司／指定範圍，我會補充／這題先略過。
- 「這份分析要幫你做什麼決定？例如比較投資方向、找出工作瓶頸，或評估已選定的方案。若還沒選方向，也可以先探索幾種可能。」可用選項：比較幾種方向／評估指定方案／尚未決定，先探索。已知目標就直接帶入，只詢問必要的時程、限制或取捨。
- 「有哪些資料適合直接提供給這次分析？可以給文件路徑、連結或口述重點，例如業務範圍、策略目標、產品與客戶資料。也可以選擇略過後續問答，先用現有資料開始。」可用選項：提供現有文件／先口述重點／略過後續問答。

整家公司是分析邊界，並不等於已選定哪個部門優先投資。明確指定局部範圍時，尊重該範圍；不得將局部結論直接提升為全公司排序。將使用者的投資偏好記為意圖，將其對業務現況的描述記為待核對的陳述，兩者分開。

## 第二輪：找出能直接使用的證據

依第一輪答案，問兩至三個最能影響判斷的問題。先說明需要回答哪個業務問題，再問有沒有相應資料。接受簡述、匿名摘要或一個代表性案件，無需索取全部企業資料。

- **業務範圍與成果：** 哪些產品、客戶或工作對這次決策重要？有無業務介紹、管理報表、客戶需求、續約、品質、交付或成本資料可用？需要核對其期間、單位和涵蓋範圍。
- **現有做法與反例：** 目前怎麼完成這項工作，已用哪些工具？有無試過卻未改善結果的做法、與原先判斷不同的客訴或案件？請提供相關紀錄或口述一件實例，讓分析能檢查既有假設。
- **資料的使用範圍：** 哪些文件能直接引用，哪些適合只用摘要？資料涵蓋哪個部門、產品、客戶或期間？合作方的功能介紹、內部規劃與已投入運作的紀錄，分別標示。

使用者提供的資料也有適用範圍。內部文件可以補足公開來源看不到的工作，仍需區分計畫、實際活動、成果與因果解釋。文件出自公司或管理層，不會自動證明某項投資應優先。

## 第三輪：只追問會改變方案的執行條件

有了候選問題後，再選少量問題深入。以下七點對應主方法的分析邏輯，作為選題依據，不是七題必填表。

1. **能否執行：** 「能否用一件實際案件，說明資料進來後由誰判斷、如何交接、誰採取行動，最後如何確認結果？」可用資料是案件、處理時間與結果紀錄。
2. **誰能維持：** 「哪個團隊可以持續負責？能投入多少審查、值班與維護時間？」可用資料是責任分工、工作量與經常成本。
3. **決策如何改變：** 「若只能先改善一種結果，現在最在意哪個？什麼情況會讓另一個目標更重要？」可用資料是策略、期限、預算限制及管理取捨。尚未決定時保留多個條件式目標。
4. **維持、監控或創新：** 「哪些工作目前可靠、需要維持？哪些已有問題或需要試新做法？依據是什麼？」不要要求使用者直接替圖上色。
5. **資料條件：** 「這件工作需要的資料是否取得得到？能否連到同一案件、時間與結果？誰能修正錯誤？」可用資料是樣本、定義、版本、更新時點與存取條件。
6. **真正需要改善的環節：** 「問題主要卡在發現、判斷、交接、執行，還是確認結果？有什麼案例支持或反駁這個看法？」同時詢問現有工具、流程調整與增加人力能解決多少。
7. **自主程度：** 「AI 可以讀取、建議或建立哪些草稿？哪些操作仍須誰核准？出錯或沒人回應時由誰接手？」記錄現有權限與建議權限，勿把使用者對功能的偏好當作正式作業授權。

每次追問要說清楚：答案會改變哪個範圍、候選或驗證方式。已經足以進行有界線的比較，就停止提問並開始分析。

## 略過、缺口與外部搜尋

- 略過一題：保留該題未明資訊，繼續其他有用問題。略過後續問答：停止這段訪談，用現有資料建立暫定範圍與條件式目標。
- 已提供的範圍、限制和文件先用於界定問題，再搜尋能補足或挑戰它們的資料。若使用者未指定局部範圍，先保留公司主要業務、客戶與合作邊界，勿讓第一個詳細產品頁選定投資切入點。
- 只補查會影響判斷的缺口。先提出競爭解釋，尋找既有功能、其他限制或被遺漏業務等實際反例，再依結果決定下一次搜尋；不把略過當成全面補滿資訊的任務。
- 記錄每個來源的機構、目的、期間、業務範圍、統計分母及原始出處。同一公告的轉載不算多份獨立證據；產品功能、部門實作與集團成效分別使用。
- 外部資料與使用者描述衝突時，先核對時點、定義及範圍。若衝突會改變決策，說明差異並針對該點追問；尚無法解決時保留兩種解釋。
- 找不到公開證據的內部成本、權限、人力或效果，維持未知。改寫為下一步需要確認的具體條件，不補上分數、批准或因果結論。

## 問答紀錄與完成條件

在研究紀錄旁保存 `intake-record.json`，避免下一個 skill 重問，也讓後續搜尋知道哪些範圍已確定。記錄必要摘要和資料位置即可。

```json
{
  "status": "in_progress",
  "scope": {"value": null, "status": "unknown", "basis": []},
  "decision": {"value": null, "status": "unknown", "basis": []},
  "period_and_constraints": {"value": null, "status": "unknown", "basis": []},
  "user_reported_facts": [],
  "provided_materials": [],
  "existing_tools_and_workflow": [],
  "counterexamples_and_alternatives": [],
  "execution_conditions": [],
  "answered_questions": [],
  "skipped_questions": [],
  "material_gaps": [],
  "research_questions": []
}
```

整體狀態使用 `in_progress`、`ready` 或 `skipped`。欄位狀態區分 `user_specified`、`document_supported`、`provisional`、`unknown` 與 `skipped`；每項依據保留答案或文件出處。`provided_materials` 記錄位置、用途、期間、涵蓋範圍、引用限制及是否已讀取；`material_gaps` 記錄缺少什麼、會改變哪個判斷，以及要問使用者還是查外部來源。

已知範圍與決策足以支持比較，或使用者已明確略過，就可進入研究。先用短句交代將採用的範圍、目標與仍待確認的條件，讓使用者能隨時修正；不另要求形式上的批准。

成品中的關注重點，來自整合資料與反例後的判斷。初始看法保留在研究紀錄；正文說明最後的事實、作用機制與條件式選擇，讓使用者看懂什麼證據會改變投入順序。
